The application is a layered FastAPI service built around `app/main.py` which creates the `FastAPI` instance, registers CORS and `RequestContextMiddleware`, installs exception handlers from `app/core/errors`, and mounts the `/api/v1` router plus a health router. The v1 router (`app/api/v1/router.py`) composes feature routers (auth, candidates, jobs, postings, pipeline, search, notifications, storage, quiz, voice_interviews, workflows) and two cross-cutting endpoints (`/interviews/token` for LiveKit tokens, `/ai/interview-questions`). Request handling follows a dependency-injection pattern: `app/api/dependencies.py` defines typed `Annotated[...]` dependencies (`SettingsDependency`, `DbDependency`, `IdentityDependency`, `CurrentUserDependency`, `EmployerContextDependency`, `CandidateContextDependency`, `PackRegistryDependency`) that resolve settings, open per-request DB connections via `app/db/database.py`, decode JWTs or accept a dev `X-Development-Identity` header, and enforce tenant/role checks. Business logic lives in `app/services/*` (auth_tokens, cv_extract, cv_parse, embeddings, matching, packs, synthesis_service, voice_interview, livekit, mail, avatars, identity, passwords), while domain concepts are isolated in `app/domain/*` (evaluation, permissions, stages). The AI subsystem under `app/ai/` implements agents (base, conversation, supervisor), prompt templates, and an orchestrator; it is exposed through `app/schemas/ai.py` and consumed by services. Persistence is engine-agnostic: `app/db/database.py` defines `Connection`/`Cursor` protocols and provides both `sqlite3` and a `PostgresConnection` adapter (with `?`→`%s` placeholder translation) so the store layer uses one SQL dialect; schema DDL and column migrations are applied at first connect. Configuration is centralized in `app/core/config.py` using `pydantic-settings` with `THOS_` env prefix, environment-aware validation, and computed properties (`database`, `cors_origin_list`, `voice_interview_ready`). Tests under `tests/` use pytest with `conftest.py` fixtures against the same database abstraction.
