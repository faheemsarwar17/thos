The repo is organized as a multi-product workspace: `Backend/` (FastAPI ATS), `Frontend/` (Next.js ATS UI), `pts/` (a separate FastAPI+Next.js performance-tracking product), plus `domain-packs/`, `infrastructure/`, and cross-cutting design/spec docs. All products share the same architectural contract defined in `architecture.md`: a Universal Hiring Engine layer that owns auth, tenancy, ATS state, interview orchestration, sandbox execution, matching, search, analytics, and automation, while domain-specific behavior lives in pluggable Domain Packs loaded through a Registry. Cross-child wiring is enforced by published contracts rather than direct imports — Pydantic schemas in `Backend/app/schemas/` define the API/event/pack contracts consumed by both Frontend and pts; a standardized request context (`tenantId`, `actor`, `unitScopeIds`, `permissions`) and event envelope (`DomainEvent<T>` with `eventId`, `eventVersion`, `occurredAt`, `tenantId`, `correlationId`) are required on every mutation and async operation across all services. The `livekit-docker-compose.yml` and `infrastructure/local/` provide shared runtime dependencies (PostgreSQL, Redis, MinIO, LiveKit) used by both ATS and pts interview flows. Deployment is modular-first: each product ships as its own containerized deployable (web, API, workers, sandbox) but shares the same outbox pattern, idempotency keys, audit records, tenant isolation via PostgreSQL RLS, and AI adapter boundaries so new domain packs or new products can be added without touching engine code.
